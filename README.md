# Скат

**Ищет жемчужины в глубинах интернета.** Скат раз в сутки собирает открытые списки VLESS‑конфигураций, находит среди них 25 по‑настоящему рабочих, проверяет их глубже и показывает 5 лучших.

## Конвейер сканирования

```text
все источники из config.txt ─→ тысячи уникальных узлов
  ↓ проверка по очереди (источники чередуются), пока не наберётся 25 рабочих
25 кандидатов ─→ глубокая проверка: 5 замеров задержки + загрузка 2 МБ
  ↓ ранжирование: задержка × штраф за сбои + время загрузки 1 МБ
5 лучших
```

**«Рабочая» означает пригодная к использованию, а не просто разобранная или принятая Xray.** Узел становится кандидатом, только если через его туннель:

1. открывается `https://www.cloudflare.com/cdn-cgi/trace` с **проверкой TLS‑сертификата**. HTTPS‑запрос идёт внутри туннеля, поэтому ошибка сертификата означает перехват трафика. Раньше для REALITY проверка отключалась;
2. ответ — настоящая страница trace, а не любая страница с кодом 200/3xx (например, captive portal);
3. **IP выхода отличается от собственного IP сканера**. Иначе трафик в прокси не попал;
4. открывается второй, независимый сайт (`gstatic.com/generate_204`);
5. **реально скачиваются 256 КБ**. DPI часто пропускает маленькие запросы и «замораживает» соединение после первых килобайт.

Замер на реальных данных до исправления: из узлов, которые прежняя проверка считала рабочими, около 30% не проходили эти условия.

Глубокая проверка: 5 замеров задержки подряд (нужно не меньше 4 успешных) и загрузка 2 МБ. Узел без завершённой загрузки в выдачу не попадает. Если рабочих узлов меньше 25 или по итогам глубокой проверки годных меньше 5, сервис честно вернёт меньше.

Страна узла — это **измеренная страна выхода** (поле `loc` из trace), а не флаг в названии из источника.

```text
Пользователь
  ↓
Vercel ─ Vue 3 + Vite (frontend/)        статический сайт, без секретов
  ↓  HTTPS, CORS
Backend ─ FastAPI (app/)                  ваш сервер / VPS / Docker
  ↓
Сканер ─ Xray + aiohttp                   один скан за раз
  ↓
Кэш ─ data/scan_*.json (24 часа)          общий для всех посетителей
```

Фронтенд и бэкенд — отдельные сервисы. Сканер **не переносится на Vercel**: ему нужен бинарник Xray, сотни одновременных соединений и минуты работы.

## Локальная разработка

Нужны Python 3.11+, Node.js 20+ и бинарник Xray (если его нет в `./xray` или `PATH`, сканер скачает его сам).

**Бэкенд** (порт 8000):

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
PYTHONPATH=. uvicorn app.main:app --port 8000 --reload
```

При первом запуске кэша нет, поэтому сразу стартует скан (около двух минут). Прогресс: `curl localhost:8000/api/scan/status`.

**Фронтенд** (порт 5173):

```bash
cd frontend
npm install
npm run dev
```

В режиме разработки `VITE_API_URL` не нужен: Vite проксирует `/api` на `http://127.0.0.1:8000`.

| `TOP_COUNT` | `5` | Сколько лучших оставить |
| `DEEP_ATTEMPTS` / `DEEP_MIN_SUCCESS` | `5` / `4` | Замеров в глубокой проверке и сколько из них должны пройти |
| `WORKERS` | `300` | Одновременных проверок внутри одного процесса Xray |
| `BATCH_SIZE` | `500` | Узлов на один процесс Xray |
| `TIMEOUT` | `4.0` | Жёсткий лимит одного небольшого запроса через узел, секунды |
| `SOURCE_TIMEOUT` | `45` | Лимит загрузки одного списка‑источника, секунды |
| `XRAY_BINARY` | `./xray` | Путь к Xray |
| `CONFIG_FILE` | `./config.txt` | Список источников |

Источники перечислены в [`config.txt`](config.txt): по одной ссылке на строку, `#` — комментарий.

## Продакшн на своём сервере

Весь стек (фронтенд, бэкенд, HTTPS) поднимается одной командой на чистом Ubuntu/Debian:

```text
https://scat-search.ru      → Caddy (systemd) → 127.0.0.1:8080 → frontend (Nginx)
https://www.scat-search.ru  → 308 → https://scat-search.ru
https://api.scat-search.ru  → Caddy (systemd) → 127.0.0.1:8000 → backend (FastAPI + Xray)
```

```bash
# на сервере, от root
scp deploy.sh root@SERVER:/root/        # или скопируйте файл любым способом
ssh root@SERVER
./deploy.sh
```

Git работает по SSH (`git@github.com:Pro100Kir2/scat.git`), токены GitHub не нужны. При первом запуске скрипт создаёт ключ `/root/.ssh/scat_deploy_ed25519`, печатает его публичную часть и останавливается: добавьте её в https://github.com/Pro100Kir2/scat/settings/keys как deploy key **без** права записи и запустите `./deploy.sh` ещё раз. Подойдёт и уже настроенный SSH-ключ root или проброшенный агент (`sudo -E`). Ключи хоста github.com скрипт берёт из https://api.github.com/meta (по HTTPS), а не доверяет первому подключению. Другой репозиторий: `SCAT_REPO_URL=git@github.com:OWNER/REPO.git`.

Скрипт идемпотентен: ставит git/Docker/Compose/Caddy только если их нет, клонирует или обновляет `/opt/scat`, создаёт `/opt/scat/.env` (секреты генерирует сам, существующие значения не трогает), собирает и запускает контейнеры, настраивает Caddy (`caddy validate` перед перезагрузкой) и проверяет сайт, API, CORS и сертификаты. Проверки HTTPS идут через Caddy самого сервера (`curl --resolve …:127.0.0.1`, сертификаты проверяются), поэтому не зависят от того, может ли сервер достучаться до собственного публичного IP. Порты 8000/8080 слушают только `127.0.0.1`. Всё, что скрипт печатает, включая причину ошибки, пишется и в `/var/log/scat-deploy.log` (строки `RESULT:` — итог каждого запуска).

Обновление после `git push`: `sudo /opt/scat/deploy.sh`. Скрипт сам проверяет состояние сервера (контейнеры, порты, `.env`, точное совпадение конфига Caddy, `caddy validate`, HTTPS) и выбирает режим: если всё в порядке — UPDATE (fast-forward, пересборка образов только при новом коммите или изменённом `.env`, `up -d`, проверки), иначе — полный SETUP с исправлением конфигурации. После успешного SETUP пишется маркер `/var/lib/scat/.initialized` с версией схемы состояния (`STATE_SCHEMA`), поэтому следующий запуск — UPDATE; правка самого `deploy.sh` SETUP не вызывает. Коды выхода: `0` — готово, `1` — ошибка, `3` — SETUP не завершён (DNS/HTTPS ещё не готовы, маркер не записан; запустите позже). Принудительно: `sudo /opt/scat/deploy.sh --setup`. Вручную:

```bash
cd /opt/scat
docker compose config          # backend + frontend (COMPOSE_FILE в .env)
docker compose build
docker compose up -d
```

`VITE_*` зашиваются во фронтенд при сборке: после их изменения в `.env` нужен `docker compose build frontend`. Все переменные описаны в [`.env.example`](.env.example).

## Деплой фронтенда на Vercel

1. **Add New → Project**, импортируйте репозиторий.
2. **Root Directory:** `frontend`.
3. **Framework Preset:** Vite (определяется автоматически).
   Build Command — `npm run build`, Output Directory — `dist`. Менять не нужно.
4. Задайте переменные окружения (см. ниже) и нажмите **Deploy**.

`vercel.json` не нужен: сайт одностраничный, без клиентского роутинга, поэтому rewrites не требуются.

`npm run build` пререндерит страницу: после обычной сборки Vite собирает SSR‑версию приложения и записывает готовую разметку в `dist/index.html` (`scripts/prerender.mjs`), а в браузере Vue её гидратирует. Поисковики и превью ссылок видят весь текст без выполнения JavaScript. Неизвестные адреса отдают настоящий 404 (`404.html`), а не копию главной.

## Vercel Environment Variables

**Settings → Environment Variables.** Всё, что начинается с `VITE_`, встраивается в JavaScript и видно любому посетителю — **никаких секретов сюда**.

| Имя | Обязательно | Пример значения | Зачем |
| --- | --- | --- | --- |
| `VITE_API_URL` | **да** | `https://api.your-domain.com` | Публичный HTTPS‑адрес бэкенда, без `/` в конце |
| `VITE_SITE_URL` | рекомендуется | `https://your-project.vercel.app` | Canonical, абсолютные ссылки Open Graph и структурированных данных, `sitemap.xml` и строка `Sitemap:` в `robots.txt`. Без него sitemap не создаётся |
| `VITE_DONATE_URL` | нет | ссылка на вашу страницу доната | Показывает кнопку «Пожертвовать» в шапке и «Поддержать Ската» в подвале. Пусто — кнопок нет. На Vercel задаётся в Environment Variables проекта |
| `VITE_GOOGLE_SITE_VERIFICATION` | нет | `AbC…` | Подтверждение прав в Google Search Console: значение `content` из их `<meta>` |
| `VITE_YANDEX_VERIFICATION` | нет | `0123…` | Подтверждение прав в Яндекс Вебмастере: значение `content` из их `<meta>` |

После изменения переменных сделайте **Redeploy**: Vite подставляет их на этапе сборки.

Затем добавьте домен Vercel в `ALLOWED_ORIGINS` на бэкенде (см. [CORS](#cors)).

> Бэкенд должен быть доступен по **HTTPS**: страница на `https://…vercel.app` не может обращаться к `http://` API (mixed content).

## Деплой бэкенда

### Docker

```bash
docker build -t skat-api .
docker run -d --name skat -p 8000:8000 \
  -v skat-data:/app/data \
  -e ALLOWED_ORIGINS=https://your-project.vercel.app \
  -e ADMIN_TOKEN="$(openssl rand -hex 24)" \
  --restart unless-stopped skat-api
```

Образ сам скачивает Xray под Linux (amd64/arm64), работает от непривилегированного пользователя и хранит кэш в томе `/app/data`.

### systemd

```ini
[Unit]
Description=Skat API
After=network-online.target

[Service]
User=skat
WorkingDirectory=/opt/skat
Environment=PYTHONPATH=/opt/skat
EnvironmentFile=/opt/skat/.env
ExecStart=/opt/skat/.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000 --proxy-headers
Restart=always

[Install]
WantedBy=multi-user.target
```

**Запускайте один процесс uvicorn** (без `--workers N`): сканер занимает локальные порты начиная с `PORT_START`. Если несколько процессов всё же делят `DATA_DIR`, lock‑файл не даст им сканировать одновременно.

### HTTPS

Поставьте перед API reverse proxy с сертификатом, например Caddy:

```text
api.your-domain.com {
    reverse_proxy 127.0.0.1:8000
}
```

За своим прокси включите `TRUST_PROXY_HEADERS=true`, чтобы лимит запросов считался по реальным IP.

## CORS

Бэкенд разрешает только перечисленные origin'ы. Credentials не используются, `*` не используется.

- **Продакшн:** `ALLOWED_ORIGINS=https://your-project.vercel.app` (и ваш собственный домен, если он есть).
- **Локально:** `http://localhost:5173` уже в значении по умолчанию.
- **Preview‑деплои Vercel** (необязательно): `ALLOWED_ORIGIN_REGEX=https://your-project-[a-z0-9-]+-your-team\.vercel\.app`. Делайте шаблон узким, чтобы он совпадал только с вашими preview.

Проверка:

```bash
curl -sI -H "Origin: https://your-project.vercel.app" https://api.your-domain.com/api/health | grep -i access-control
```

## Кэш и защита от повторных сканов

```text
GET /api/results
  ↓
кэш есть и свежий? ── да → ответ из кэша
  ↓ нет
скан уже идёт? ── да → присоединиться к нему (новый не запускается)
  ↓ нет
запустить один скан в фоне → сохранить в кэш → все ждущие получают результат
```

- **24 часа.** Результат лежит в `data/scan_all.json` вместе с `created_at`, `expires_at`, числом узлов и `scanner_version`. Запись атомарная, так что читатели никогда не видят половину файла.
- **Single‑flight.** 100 одновременных запросов при пустом кэше дают **один** скан (покрыто тестом). Внутри процесса запросы присоединяются к общей задаче asyncio; между процессами работает `fcntl`‑lock.
- **Stale‑while‑revalidate.** Пока идёт новый скан, отдаётся предыдущий результат с `cache_state: "stale"`.
- **Отдельный кэш на каждый запрос.** Общий улов — `data/scan_all.json`, поиск по стране — `data/scan_DE.json` и т. п. У каждого свои 24 часа и свой single‑flight. Сканер работает строго по одному: поиски по разным странам встают в очередь, её длина ограничена `MAX_QUEUED_SCANS`.
- **Версия сканера.** `SCANNER_VERSION` в [`app/config.py`](app/config.py). Меняйте её при изменении логики проверки или ранжирования — кэш старой версии будет проигнорирован.
- **Неудачи.** Скан без результатов (например, в стране нет рабочих узлов) кэшируется на 1 час, а не на 24. После ошибки новые запросы 5 минут не запускают повторный скан.
- **Наблюдаемость.** В `/api/scan/status` видны состояние кэша, прогресс (сколько найдено из 25, сколько узлов проверено) и признак `queued`, в логах — `skat.cache` и `skat.scanner`. `GET /api/admin/stats` с токеном показывает счётчики попаданий в кэш и текст последней ошибки.

Принудительные действия (нужен `ADMIN_TOKEN`):

```bash
curl -X POST -H "Authorization: Bearer $ADMIN_TOKEN" https://api.your-domain.com/api/admin/scan
curl -X POST -H "Authorization: Bearer $ADMIN_TOKEN" https://api.your-domain.com/api/admin/cache/clear
```

## Кнопка «Поддержать Ската»

Платёжные реквизиты в проекте не хранятся и не придумываются. Кнопка появляется, только когда задан `VITE_DONATE_URL` — ссылка на Boosty, CloudTips, Ko‑fi или любую другую страницу. Принимаются только адреса `http(s)://`.

Кнопка показывается в двух местах: после списка результатов (когда человек уже получил пользу) и в подвале.

## Зонды провайдеров

Сканер отвечает на вопрос «работает ли конфигурация?». Зонды отвечают на другой: «открывается ли этот сервер из сети конкретного провайдера?». Это маленькая программа на Go на устройствах добровольцев (роутер с OpenWrt, Raspberry Pi, ПК). Она **не запускает VLESS и Xray**, не открывает входящих портов и не выполняет команд: только проверки TCP, TLS и HTTP GET по строгой схеме, и только до публичных адресов.

- После каждого полного скана 25 лучших кандидатов становятся целями; каждый онлайн-зонд получает по заданию на уникальный адрес (результаты кэшируются на `PROBE_RESULT_TTL_SECONDS`). Загрузка страницы и поиск по стране проверок не запускают.
- В раскрытой карточке конфигурации — «Доступность в сетях»: доступен, недоступен, нет ответа, проверяется, нет зонда, зонд офлайн, не проверялся.
- Раздел сайта `/providers/`: доступные провайдеры и состояние зондов; `/providers/add/`: форма и установка (интерактивная или ручная); `/providers/install/`: инструкция.
- Установщик сначала проводит диагностику и спрашивает сервер SUPPORTED/UNSUPPORTED; не подходит — ничего не скачивает. Бинарники для x86_64, x86, ARM64, ARMv5–7, MIPS/MIPS64 (обе байтовые последовательности), RISC-V собираются в `Dockerfile` бэкенда и отдаются с SHA-256.
- Новые зонды ждут одобрения администратора (`POST /api/admin/probes/<id>/approve`): до этого их результаты не учитываются. Состояние хранится в SQLite `DATA_DIR/probes.db`.
- В продакшне обязательно задайте `PUBLIC_API_URL` (deploy.sh делает это сам).

Архитектура, API, безопасность, OpenWrt и разбор проблем: [docs/PROBES.md](docs/PROBES.md).

## API

| Метод | Путь | Описание |
| --- | --- | --- |
| `GET` | `/api/results` | Результаты для сайта и состояние кэша. Если кэш пуст или устарел, запускает скан |
| `GET` | `/api/scan/status` | Лёгкий статус для опроса во время скана |
| `POST` | `/api/scan` | «Начать поиск»: `cached` / `started` / `joined` / `cooldown`. С лимитом запросов |
| `POST` | `/api/cache/refresh` | «Очистить кэш»: свежий скан в обход кэша, старые результаты видны до его конца. Не чаще раза в `REFRESH_COOLDOWN_SECONDS` на всех (иначе `429` с `Retry-After`) |
| `GET` | `/api/vless/search/{country}` | Тот же конвейер только для узлов с выходом в стране (`DE`, `nl`…): **200** — результат из кэша, **202** — поиск в очереди или идёт (повторяйте запрос), **422** — неверный код, **503** — очередь занята (`Retry-After`) |
| `GET` | `/api/vless/sub?limit=5` | Подписка для клиентов (base64) |
| `GET` | `/api/vless/raw?limit=5` | Ссылки обычным текстом |
| `GET` | `/api/vless/top?limit=5` | Лучшие узлы во внутреннем формате (для старых скриптов) |
| `GET` | `/api/sources` | Источники и их состояние в последнем скане |
| `GET` | `/api/health` | Проверка живости |
| `POST` | `/api/admin/scan`, `/api/admin/cache/clear` · `GET` `/api/admin/stats` | Только с `Authorization: Bearer $ADMIN_TOKEN` |

`/api/scan/start` сохранён как псевдоним `POST /api/scan`. Интерактивная документация — `/docs`.

## Безопасность

- **SSRF.** Сканер ходит только по адресам из `config.txt` на сервере и по фиксированным адресам проверок. Пользовательский ввод целей сканирования не принимается.
- **Злоупотребление сканом.** Публичные запросы не могут запустить скан, пока кэш свежий. Поиск по стране принимает только двухбуквенный код, ставит сканы в очередь ограниченной длины и учитывает в лимите только запросы, которые действительно запускают скан. Одновременные запросы объединяются, `POST /api/scan` ограничен по IP, после ошибки действует пауза. Удаление кэша требует `ADMIN_TOKEN` (сравнение за постоянное время). Кнопка «Очистить кэш» ничего не удаляет: `POST /api/cache/refresh` запускает свежий скан не чаще раза в 10 минут на весь сервис (таймер на сервере, а не только в браузере) и учитывается в лимите по IP. Раньше `/api/cache/clear` был открыт всем.
- **Утечки.** Клиенту не отдаются тексты внутренних ошибок и пути. Во фронтенде нет секретов: `VITE_*` — только публичные адреса.
- **XSS.** Метки узлов из источников выводятся как текст и дополнительно очищаются от ссылок и рекламы. `v-html` используется только для SVG QR‑кода, который генерируется локально. Ссылка доната принимается только с протоколом `http(s)`.
- **Сторонние сервисы.** QR‑код строится в браузере. Прежний интерфейс отправлял конфигурацию на `api.qrserver.com`.
- **Честность.** На сайте прямо сказано, что это публичные серверы без гарантий приватности.

**Анимация без тяжёлых зависимостей.** Скат — небольшая 3D‑модель на Canvas 2D. Контур деформируется волной взмаха, которая бежит от тела к кончикам крыльев, затем поворачивается по крену, тангажу и рысканию и проецируется камерой, смотрящей в воду сверху. Тяга приходит на взмахе вниз, поэтому скорость пульсирует. Разворот идёт через глубину, скат кренится в поворотах, иногда планирует, обследует дно и сторонится курсора. Статичные слои сцены рисуются один раз при изменении размера. Анимация останавливается, когда сцена не видна или вкладка скрыта. Для `prefers-reduced-motion` показывается неподвижная композиция, а жемчужины появляются сразу.

**Жемчужины — это реальные данные.** Во время живого скана каждая новая рабочая конфигурация (`working_candidates`) становится жемчужиной. Скат подплывает к месту находки, и только после этого увеличивается счётчик. Если свежий улов уже есть в кэше, погружение показывает его. Клик по жемчужине ведёт к её карточке .
